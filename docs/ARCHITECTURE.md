# Architecture

Source of truth for rules and numbers: `docs/GAME_SPEC.md`. This file says where things live and how they talk.

## Data flow

```
TikTok LIVE ──► apps/bridge (Node)
                 validate → dedupe → merge combos → limits → units/tier → SQLite
                 └─► WebSocket ws://localhost:7420 ──► apps/game (Three.js, 1080x1920)
apps/host (localhost:7421) ── simulator events ──► apps/bridge   (same path as TikTok)
apps/desktop (Electron) opens apps/game in one window "The Temples"
TikTok LIVE Studio (Vertical) ── Game Capture of that window + face cam + mic ──► stream
```

Backup capture: LIVE Studio Link source at `http://localhost:5173`, size 1080x1920.

## Look (D25)

`apps/game/src/engine/look.ts` sets the animated-film look once: ACES tone mapping, one warm sun with PCF soft shadows (map size per preset), an environment map made from the sky, gradient sky dome, clouds and horizon hills that follow the camera, and `addRim` (edge glow) for Standard materials. `engine/figures.ts` builds characters from rounded shapes; each vertex carries `limb` / `limbZ` so the vertex shader swings legs and arms, rolls wheels and sways trunks per instance (`gl_InstanceID` phase) — no skinning, one draw call per crowd. Presets in `config/quality.json` (`low` default, `high`, `lite` without shadows); the desktop window picks one via `config/window.json` → `preset`.

## Low-poly style (D41)

`engine/look.ts` holds the style switch (`look.style` in `config/quality.json`). Geometry code asks `seg(n)` / `detail(n)` for segment counts, so round shapes are built with half the segments in the low-poly style. Before each render `styleScene()` walks the scene once per new material: lit materials get `flatShading`, and textures marked `userData.detail` (brick, laterite, sandstone, ground, grass, thatch, grain) are replaced by their average colour. Pictures such as the painted map and carved names, and cut-out textures, are kept. Ground planes get a small random lift per vertex so flat ground shows facets. `?style=film` brings back the D25 look.

Graphics memory (D143): three.js never frees GPU buffers by itself. `engine/dispose.ts` `disposeNode(node, { textures?, keep? })` frees geometry, materials (and textures when asked), instance buffers, bone textures and shadow maps under a node and takes it out of its parent; `disposeAndRemove(scene, node)`. Resources marked `userData.shared` are spared. Whatever replaces a world or a model calls it: `KingdomScene.dispose()` on New Game / Load, `KingdomPost` for its passes, the hero's ground and rig, the court redressed for a new era, a prop's replaced material.

## Site crew, animals and countryside (D43–D45)

`world/worksite.ts` is the crew's rules, pure and unit-tested: roles (hauler, carver, lever, puller), one state machine each, sliding around the towers, a one-minute warm-up on the first frame so the site opens busy. `scenes/site.ts` draws it with three crowds (bare hands, mallet, bamboo pole), blocks carried on heads, the carving yard, the rope, beam and rising block, and scaffolding ledgers. The crowd shader reads a per-instance `act` attribute (`ACT` in `engine/figures.ts`: stand, hammer, lift, pull, lever, carry); 0 keeps the crowd's own walk. `engine/animals.ts` builds animals by lofting elliptical cross-sections along the spine (`loft()`), with jointed tube legs that swing on the GPU. `world/landscape.ts` is the countryside (instanced paddies, palms, villages, reservoir, herds). `apps/game/gallery.html` (dev server only) shows every animal and crew pose side by side for art review; `?offline=1&progress=0.5` previews a half-built site without the bridge.

## Khmer Kingdoms, the RTS tab (D46–D49)

Data: `config/kingdom/` (eras, sources, buildings, units, techs, rules) loaded and validated by `packages/shared/src/kingdom.ts` (`loadKingdom`, `validateKingdom`). Rules: `apps/game/src/kingdom/sim/` is pure and unit-tested: `map.ts` (seeded Hariharalaya map, walk grid, A* with string-pulling), `sim.ts` (entities, commands, gathering, construction stages, queues, research, combat, rival AI, fog of war, victory), `save.ts` (versioned saves, checksums, slots, backups, migration). Drawing: `view/scene.ts` (terrain, water, instanced trees/rocks/buildings, team-coloured crowds with per-instance actions, rings, health bars, arrows, fog veil, placement ghost; the monument is the real Preah Ko kit via `TempleView`), `view/art.ts` (low-poly models), `view/hud.ts` (16:9 HUD, minimap). `kingdom.ts` glues input, camera, command panel, LIVE support, council vote and saves. Mode `kingdom` flows through the bridge like the others; `control/kingdom` (save, load, new) is broadcast as `command/kingdom`. `?mode=kingdom&offline=1&kingdomDemo=1` opens a demo kingdom without the bridge. Layout (D51): `stage.ts` `setLayout('landscape' | 'portrait')` switches the stage and render size between 1080×1920 and 1920×1080 and asks the desktop app (preload `templesDesktop.setLayout` → IPC `temples:layout`) to resize its window; `windowSize.cjs` `landscapeSize()` picks the 16:9 size.

Campaign (D53–D56): `config/kingdom/campaign.json` (map scale, resources, opponents, 13 chapters: temple, era, year, opponent, footprint, form, events, history, sources) and `config/map.json` (the Build map) feed `map.ts` `templeSites()` / `generateMap()` (one 340 × 340 tile map, sites nudged apart, island rings, Angkor Wat moat, Kulen hills). `sim.ts` keeps `chapter` and `completed`, `allows()` from `eraContent()`, and `completeChapter()` (era end, next temple, new rival camp, new hall for a capital move); save v2 stores both. `view/temples.ts` builds each temple from its `form` (clipped while it rises); `view/scene.ts` draws them at their sites, the site marker, opponent colours and headwear, east-facing houses, and a camera-window of trees; `view/hud.ts` renders the chapter header, History timeline, chapter cards and minimap temple marks; `kingdom.ts` handles History, visits (camera flight) and chapter events.

Empire world (D60–D66): `config/kingdom/world.json` (size, origin of the Greater Angkor block, lake, rivers, sea, ranges with passes, massifs, rainforest, places, neighbours, resources, fish, animals) is validated by `WorldSchema` in `packages/shared/src/kingdom.ts`. `map.ts` `generateMap(data, seed)` (cached) lays down the world, then the Greater Angkor block, then seeded resources and forests; `MapData.seed` and `places`. `sim.ts` adds `animals` (herds, tigers, respawn), fish regrowth, the `hunt` task, `discovered` places, `weather`, `autoWork` (`findWork`/`jobFor`), `guard`, waypoints, long walks in legs, and the raid gate (`rules.raids`). Save v3 stores the seed and changed nodes only. Drawing: `view/weather.ts` (`WeatherFx`: light, haze, rain Points), `view/icons.ts` (`IconAtlas`: 3D button sprite sheets drawn with the game renderer), `view/temples.ts` `landmarkGeometry`, `engine/animals.ts` (deer, boar, tiger, banteng, fowl), `engine/wildlife.ts` (Cambodia's forest wildlife, D75; looks in `view/wildLook.ts`, behaviours by config in `updateAnimals`), `engine/figures.ts` (`LIMB.forearm`, acts thrust / sword / draw / guard / plant), `view/art.ts` `swordsmanGeometry`. `kingdom.ts` adds the menu bar actions, hover hints (`updateHover`, `hint`), place labels and floating gains.

AoE-style view, army and people (D67–D71): `config/kingdom/characters.json` (occupations) is validated by `validateCharacters()`; `rules.json` gains `army` (commander aura, supply healing, watchman), `commanders` (names by era) and `livestock`. `sim.ts`: unit roles cavalry/support/scout/commander, `max` per unit, `commanderRank`, `nearCommander()`, `supply()`, `scout()`/`exploreTarget()`, event `found`; save keeps `commandersRaised` and `reported`. Drawing: `view/people.ts` (villagers by job, soldiers by era, commander, watchman, horseman, buffalo rider, ox-cart; `eraLookOf`), `view/beasts.ts` (dog, buffalo), `view/houses.ts` (Rong, Keung), `view/livestock.ts` (pig, chicken, cow), `view/vfx.ts` (`Particles`), `view/sound.ts` (`KingdomSound`, `sfxForEvent`), `view/weather.ts` (rain splashes, windy leaves, `wind`/`rain` getters), `view/ancientMap.ts` (`AncientMap`, `mapViewOf`). `scene.ts` keys crowds by type, team, era and job (`jobOf`), draws livestock and work bursts and collects work sounds; `CAM_YAW`/`CAM_PITCH_DEG` set the diagonal view and `kingdom.ts` pans along it. Dev pages: `/gallery.html?people=1`, `?houses=1`, `/vfx.html`, `/ancientmap.html`.

Background music (D76): `config/kingdom/music.json` is validated by `loadMusic()` (`packages/shared/src/music.ts`). `view/music.ts`: pure `Composer` (seeded phrases), `PhraseScheduler` (look-ahead on the audio clock), `TrackPicker`, `MoodTracker`; `KingdomMusic` (WebAudio instruments, PK's tracks, crossfade) is owned by `KingdomSound` and plays through its master and limiter. `kingdom.ts` starts/stops it with the tab and sets the mood about once a second. `apps/game/tools/musicFiles.ts` (Vite plugin) serves and copies `apps/game/public/music/`.
